## Objective

Decide HOW to wake a 0-replica app on request. Full Knative is already ruled out (see the milestone README Decision). The real choice is buy-vs-build for the activator: KEDA's HTTP add-on (off-the-shelf interceptor + scaler) vs. a lean custom Go activator. Prototype enough to decide.

## Context

- **KEDA http-add-on**: an HTTP "interceptor" buffers the request and a scaler drives 0↔N — an activator without writing one. Far lighter than Knative Serving (no revisions / networking layer).
- **Custom**: a small Go service (look up the App, patch replicas, wait Ready, proxy) — Render's end-state; most control, best aligned with the density thesis.
- Judge on: fit with the `App` CRD + Traefik edge, per-app overhead, cold-start latency, operability.

## Steps

1. Stand up KEDA http-add-on on the app cluster; wake a demo app 0→1 through its interceptor.
2. Sketch the custom-activator path (how Traefik routes to it, how it scales + proxies).
3. Write a one-paragraph decision: KEDA-add-on or custom, and why.
